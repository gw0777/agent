🔧 개선 피드백 — 보강·수정 필요 부분

⚠️ Vercel 연결 — 근본 원인 해결 안 됨

JEV 호출 실패 원인이 'Vercel 계정 신용카드 미등록'(403)이라는 것은 정확히 특정했으나, 사용자가 직접 카드 등록해야 풀리는 문제는 우리가 해결 못 함. JEV 대시보드 HTML은 만졌지만 실제 호출 성공한 데이터는 없음.

→ 개선: (1) 사용자에게 '신용카드 등록하면 바로 JEV 호출 성공함'이라고 명확히 안내한 상태인지 재확인. (2) 신용카드 등록 이후 브라우저 대시보드에서 실제 호출 → 결과 시각화까지 한 번에 시연하는 시나리오 준비. (3) API 키 만료·재발급 관리도 고려.

⚠️ GPT Bridge — 서버 안정성·자연스러운 연동 부족

gpt-bridge-server/server.py가 Flask(원본) → stdlib http.server로 재작성됐는데, 원본의 pip dependencies(requirements.txt)를 제대로 설치하지 못해 Flask 실패. Flask는 나중에 python3 -m pip install로 설치 성공했으나, 서버 프로세스는 백그라운드 실행 시 종종 죽는 현상. ChatGPT Desktop config.json은 템플릿만 만들었고 실제 ChatGPT에서 MCP 도구 노출 확인은 못 함.

→ 개선: (1) requirements.txt에 flask 고정하고 `python3 -m pip install -r requirements.txt` 한 번에 설치하는 절차 정리. (2) 서버 백그라운드 실행 안정화(더 robust한 방식 또는 systemctl·작업 스케줄러). (3) ChatGPT Desktop config.json을 실제로 병합하는 방법(윈도우 경로 `%APPDATA%\OpenAI\ChatGPT\config.json` 존재 확인 → 기존 파일에 MCP 서버 블록 추가) 안내 보강. (4) VS Code 확장이 마켓플레이스에 없어서 설치 실패 → '수동 설치 vs 직접 서버 실행' 중 어떤 경로가 교수님께 더 나은지 선택 정리.

⚠️ GitHub 연동 — 원격 저장소 생성·연결 미완성

로컬 git init·commit은 완료했으나, GitHub 원격 저장소 생성(브라우저/PAT 없음)과 push는 미완. gh CLI 없음, 브라우저 자동화 실패, PAT 없음. 사용자가 GitHub에서 직접 저장소 만들고 원격 연결해야 함.

→ 개선: (1) 'GitHub에서 새 저장소 만들고 이 명령어 실행'이라는 안내(README.md에 이미 있음)를 더 눈에 띄게. (2) gh CLI 설치·PAT 발급을 사용자가 할 수 있도록 단계별 안내. (3) README.md에 '원격 연결 완료 후 이 명령어 실행' 체크박스 추가.

⚠️ 미래라이프대학 문서 — 실제 학교 양식·정합성 확인 필요

4종 문서는 바탕 자료(hwpx 2종)를 잘 해석해서 만들었으나, 실제 학교의 규정 양식·학칙 체계·용어(등기·운영세칙·규정 조·항·호 번호 체계 등)와 정확히 일치하는지 확인 못 함. 특히 규정(안)의 조·항·호 번호, 학점 수치(120학점·전공 최대 91학점·교양 29학점 등)가 실제 학교 기준과 맞는지 검증 필요.

→ 개선: (1) 규정(안)의 조·항·호 번호를 학교 실제 학칙 체계와 대조. (2) '전공 최대 91학점·교양 29학점·총 120학점' 수치가 학교 기준인지 확인. (3) 참여기업 목록은 '예시'로 표시했으나, 실제 협약 기업 리스트가 생기면 교체. (4) 교수님에게 '이 수치는 실제 학교 기준인가요?' 확인 질문 체계적인 템플릿 마련.

⚠️ 특수학급 자료 — 학교 실제 상황과의 정합성

특수학급 서비스러닝 자료(실습일지·전달사항·수업에 용도)는 일반적인 특수학급 운영 모델을 바탕으로 작성했으나, 배치될 초등학교의 실제 특수학급 구성(학생 수, 교과 운영 방식, 통합 정도, 치료 연계 유무, 담임 교사 체제 등)과 정확히 맞는지 확인 못 함.

→ 개선: (1) 배치 학교의 실제 상황(몇 명, 어떤 형태로 운영, 통합 비율, 교사 수 등)을 파악해서 자료 수정. (2) 실습일지의 관찰 초점이 실제 학교 상황과 맞는지 체크. (3) '기관별 역할 분담' 섹션(서비스러닝 학생이 배울 것/도울 것)을 실제 학교 상황에 맞게 구체화.

🚨 가장 시급한 미해결 — Vercel 신용카드 + JEV 실제 호출 성공

JEV 브라우저 대시보드는 만들었지만 실제 호출해서 결과 받아본 적이 없음. 신용카드 등록 → API 키 정상 작동 → 대시보드에서 호출 → 결과 시각화까지 이것이 완료돼야 'JEV 연결'이 진짜 완료됨. 현재 상태: 대시보드 HTML는 준비됨, API 키(env에 있음), 호출하면 403(신용카드).

→ **최우선 액션**: (1) 사용자에게 'Vercel 대시보드 → 팀/계정 → 결제/신용카드 등록 → 무료 크레딧 활성화' 절차를 다시 명확히 안내. (2) 등록 완료되면 내가 JEV 호출 테스트 즉시 수행. (3) 호출 성공 결과를 브라우저 대시보드로 시각화해서 사용자에게 보여줌. 이 단계가 완료돼야 전체 기술 트랙이 마무리됨.
